# Поиск игрового ядра и клиента

Проверено 4 ноября 2026 года. Кэш и текстуры на этом этапе отложены.

## Результат поиска

Найдены открытые реализации игровой логики GTA SA и сетевого клиента SA-MP. Готовой проверенной основы, которая одновременно работает на iOS и совместима с текущим Arizona Mobile, среди проверенных проектов не обнаружено.

Нужны две независимые части: переносимое игровое ядро и протокол Arizona. Наиболее конкретная основа для транспорта — `mishpro-programm/sampraknet`. Для независимой игровой логики найдены SanAndreasUnity и OpenSA; они используют другие runtime и не предоставляют готовую интеграцию с Arizona.

## Где логика в нашем APK

`libag-client.so` содержит JNI Init/Step/Pause/Resume, ввод, HUD, следы librw, UDP и Boost.Asio. Отдельной libGTASA.so нет. По этим признакам основная игровая реализация находится в объединённом нативном модуле; границы всех внутренних подсистем не восстановлены.

В release-библиотеке отсутствует обычная .symtab. Динамические экспорты раскрывают Android-мост, но не внутренние CGame/CNetGame/RPC-таблицы. Исходники libag-client по выполненному поиску не найдены. Совпадение имени движка/транспорта не является доказательством совпадения реализации.

Для сопоставления с исходниками/символами владельцев: Build ID ARM64 `aa6842bb687e38dd65ad2a594ac216578c449b32`, ARMv7 `4199ece5d5761e1919d3fb4034ab99a8cb64dd99`. Размер .text соответственно 7 453 064 и 6 045 724 байта.

Точная версия протокола Arizona, собственные RPC, handshake, проверка клиента и расширенная синхронизация пока не установлены. Не выполнялись запуск APK, попытки авторизации или подключения к боевым игровым серверам.

## Найденный готовый iOS-клиент: ReSA

Найдена актуальная [официальная страница ReSA для iOS](https://resa-mp.com/download?platform=ios): версия **1.1.3**, заявленный размер **44,4 MB**, iOS **15.1+**. Автор заявляет собственные игровой/сетевой движки и поддержку SA-MP/open.mp, ввод адреса сервера вручную. На странице есть IPA для самостоятельной подписи; регистрация тестера требуется для отдельного варианта прямой установки.

Это самый близкий найденный готовый iOS-клиент. Но поддержка SA-MP/open.mp не доказывает поддержку текущего Arizona Mobile. Открытые исходники iOS-ядра, SDK и подтверждённая спецификация Arizona для него не найдены. Готовый бинарный клиент не является исходным проектом для включения в нашу сборку.

Ссылка страницы ведёт на `https://resa-mp.com/api/download/ios/resa-ios-1.1.3-fbb34b5f4a9e.ipa`. Опубликованный SHA-256: `fbb34b5f4a9eee6871e6ec9ea1a2ace9864a85962dd8496884596fa517a8820b`. Прямая загрузка вернула HTTP 403; последующая загрузка через официальную кнопку в браузере удалась. Размер 46 529 349 байт, SHA-256 совпал с опубликованным. Выполнен статический разбор девяти ARM64-модулей; см. [проверку совместимости](protocol-compatibility.md). Никакой установки/запуска ReSA и подключения к Arizona не выполнялось.

Старая [страница ALYN](https://alynsampmobile.pro/download/ios) всё ещё сообщает о закрытой бете и отсутствии сборки; актуальная отдельная страница ReSA уточняет картину. Android-исходники ALYN 17.x нельзя считать исходниками iOS ReSA. Ограничения доступа не обходились, сообщения авторам от имени пользователя не отправлялись.

Дополнительно проверен [GTA-SA-FOREVA](https://github.com/0FL01/GTA-SA-FOREVA): README прямо определяет Godot-направление как визуальную лабораторию, а Linux-направление как частичный gameplay slice. Полного iOS-ядра/Arizona-клиента это не даёт; упомянутый отдельный каталог gta-reversed не представлен исходниками в проверенном дереве основного репозитория.

## Следующий проверяемый шаг

Добавлен `NetworkProbe/` и отдельный workflow **SA-MP transport iOS portability**. Он получает фиксированный sampraknet commit, компилирует и связывает библиотеку с маленькой собственной программой для iPhone ARM64 и Simulator x86_64. Проверяются размеры ID и legacy timestamp. Программа не запускается, игровой протокол с серверами не используется. В артефакты попадают только логи; библиотека не включена в приложение.

**Результат:** [проверка 41851380428](https://github.com/kup3r/arizona-ios/actions/runs/41851380428) прошла успешно. В обоих случаях библиотека и потребитель скомпилированы и связаны. lipo подтвердил архитектуры ARM64/x86_64, vtool — платформы IOS/IOSSIMULATOR, deployment target 16.0 и SDK 18.5. Статические проверки размеров MessageID, PlayerIndex и RakNetTime пройдены. Проверки чтения заголовков не выполняют полученные программы.

Это подтверждает только компиляцию/линковку выбранной версии с Apple SDK. В исходном транспорте остаются предупреждения о преобразовании целых в указатели в RPCMap, устаревшем sprintf и выключенном _RAKNET_THREADSAFE. Они не объявляются безвредными: до runtime-интеграции нужны аудит ABI/потоков и тесты на локальном согласованном сервере. Полный wire-format и поведение соединения не проверены. Сборка также не является аудитом лицензий.

После этого нужны: подтверждение протокола Arizona на разрешённой трассе/тестовом сервере; выбор игрового backend; связывание RPC с игроками, транспортом и объектами. Для игрового backend наиболее прямой путь — исходники владельцев Arizona; независимый движок — отдельная большая реализация поведения игры.

Источник по происхождению sampraknet: [OpenSAMP THIRD-PARTY-NOTICES](https://github.com/bssth/opensamp/blob/a05717eeab2de65d1def7e7725dc1985198400f7/THIRD-PARTY-NOTICES.md). Проблемы лицензий отдельных добавлений записаны, а не предполагаются решёнными наличием публичного репозитория.
