# Проверка ReSA ↔ Arizona Mobile

Проверено 4 ноября 2026 года. **Работающее подключение ReSA к Arizona Mobile не подтверждено.** Найден настоящий iOS-клиент с игровым модулем, но открытой реализации расширений Arizona или доступного исходного iOS-ядра это не даёт.

## Что проверено

1. В DEX APK прослежен вызов `ServersList.gameServersMobile()` до маршрута `/launcher/servers/arizonaMobile`. Основной и резервный API вернули HTTP 200 и одинаковый список трёх серверов. Это актуальный ответ API, а не только старый список из ресурсов APK.
2. На каждый Mobile-сервер отправлено по одному стандартному SA-MP запросу `i`, `r`, `p`. Для контроля проверен Arizona Prescott PC. Использован [документированный формат open.mp](https://open.mp/docs/tutorials/QueryMechanism). Вход в аккаунт, RCON и запрос списка игроков не выполнялись.
3. Все запросы завершились таймаутом и с Windows, и со стандартного GitHub runner. Контроль также не ответил: результат не позволяет отличить фильтрацию UDP, отключённые query и особенности протокола. Query — отдельный механизм; даже его успешный ответ не подтвердил бы игровой handshake/RPC.
4. Официальная ReSA IPA скачана через кнопку на [странице iOS](https://resa-mp.com/download?platform=ios), без установки и запуска. Прямые запросы загрузчика из Python/Actions получили HTTP 403. Полученный браузером файл имеет размер 46 529 349 байт и SHA-256 `fbb34b5f4a9eee6871e6ec9ea1a2ace9864a85962dd8496884596fa517a8820b`, точно совпадающий с опубликованным.
5. В ZIP статически прочитаны Info.plist, Mach-O load commands, таблицы символов и ASCII-строки девяти исполняемых модулей. Недоверенный код не выполнялся.

## Что находится в ReSA IPA

Bundle `com.alyn.resamp.launcher`, версия 1.1.3 (113), минимум iOS 15.1. Все девять проверенных Mach-O — ARM64. Поле cryptid равно 0; это характеристика шифрования исполняемого файла, а не оценка безопасности или прав на его использование.

| Модуль | Наблюдение |
| --- | --- |
| ReSALauncher | Связан с Flutter и ReSAEngine |
| App.framework | Flutter-приложение/интерфейс, содержит тексты выбора версий протокола |
| ReSAEngine.framework | 16 583 040 байт; ссылки на Metal, OpenAL, WebKit; строки версий 0.3.7, 0.3.7-R5, 0.3.DL, 0.3.DL-R1; сообщения omp-cef и SampBridge |
| alloader.framework | Lua-интерфейсы RakNet BitStream |
| bass.framework | Аудиобиблиотека |
| Остальные | Flutter, AppLovinSDK, objective_c, libFlutterPluginsGenerated |

[Разработчик заявляет](https://resa-mp.com/features) поддержку SA-MP/open.mp, переключение версии, mobile client ID, samp-cef/omp-cef и custom models. Наличие строк в IPA согласуется с частью этих заявлений, но не проверяет их работу.

В ASCII-строках девяти модулей не найдены `arizona`, `mobile1.arizona`, `InstallAuthorization`, `Cef3D`, `.aetex`. В Android-библиотеке Arizona присутствуют InstallAuthorization, JNI Cef3D и .aetex. Это **различие наблюдаемых маркеров**, а не доказательство отсутствия реализации: строки могут отсутствовать при другой архитектуре, быть упакованы или приходить динамически. Последующая [проверка вызовов](connection-comparison.md) установила: InstallAuthorization вызывает Android-интерфейс, а не доказывает отдельный сетевой handshake. Стандартный CEF и mobile ID сами по себе не подтверждают поддержку интерфейса, ресурсов и проверки клиента Arizona.

Из этих наблюдений нельзя установить конкретные номера Arizona RPC, значения handshake, способ авторизации или совместимость синхронизации. Открытые исходники актуального ReSAEngine не найдены в проверенных источниках. IPA не является SDK, а публичная загрузка не предоставляет автоматически лицензию на встраивание/распространение модуля. Личное использование также не создаёт такую лицензию; условия компонентов и права на игровые данные нужно проверять отдельно.

## Решение для arizona-ios

Пока **не интегрировать ReSAEngine в наш проект и не называть текущую IPA игровым клиентом Arizona**. Наш Resource Lab остаётся просмотрщиком; успешная компиляция sampraknet с Apple SDK подтверждает только переносимость сборки транспорта.

Следующая проверка, которая действительно уменьшит неопределённость:

1. На собственном Android-устройстве записать короткую трассу штатного клиента: запуск → подключение к одному Mobile-серверу. Аккаунтные токены и содержимое приватных сообщений не публиковать. Установить этапы соединения, версии и размер/направление пакетов, ничего не обходить.
2. Если владелец устройства решит испытать ReSA, использовать отдельную установку с обычными данными GTA, указать тот же адрес и собрать client.log/resa_debug.log. Разделить результаты: сервер достижим → handshake принят → показан вход → игрок создан → работают пешая/автомобильная синхронизация и интерфейс. До этого кэш Arizona не переносить.
3. По первому несовпадающему этапу решать между поддержкой со стороны авторов ReSA, доступом к исходникам Arizona и самостоятельной реализацией адаптера на открытом транспорте. Отказ проверки клиента не обходить. Для независимого клиента отдельно нужен полноценный игровой runtime.

Эти действия на телефоне в текущей проверке не выполнялись. Здесь нет подключённого iPhone и полученной трассы штатного соединения. Статический анализ не может заменить такой тест.
